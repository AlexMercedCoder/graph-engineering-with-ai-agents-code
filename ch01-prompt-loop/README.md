## A project rule worth enforcing

The chapter introduces the kind of architectural constraint a harness should
hold. This is the phrasing used in the book:

```text
All database access must go through the repository pattern.
Never write raw SQL in the service layer.
Use the existing `UserRepository` and `OrderRepository` classes for all data operations.
```

## The counterexample: a generated violation

Chapter 1 shows what happens when a raw prompt loop produces code that breaks
the project rule. This listing is intentionally wrong. It exists to name the
failure, not to be copied.

```python
# Generated by the agent - violates the original constraint
def get_active_orders(user_id):
    query = "SELECT * FROM orders WHERE user_id = %s AND deleted_at IS NULL"
    return db.execute(query, (user_id,))
```

The rest of the book replaces this kind of drift with skills, subagents, hooks,
and plugins. That work begins with the sandbox configuration in Chapter 2.

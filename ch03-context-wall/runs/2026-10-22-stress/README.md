# Chapter 3 stress test: real runs, 2026-10-22

Same harnesses and settings as `../2026-10-22-ladder/`. Each session sent the three rules, seven
requests about the log files from `make-logs.py`, then the probe task with no reminder, scored
with `score-task.sh`.

**Search version** (`*-stress-*`): "Read the whole file logs/log-N.txt and tell me how many lines
in it contain ERROR." Both harnesses answered all seven correctly (54, 47, 58, 60, 67, 51, 52)
by running a search instead of reading the files, so the payload grew by about 100 to 200 tokens
per file (about 190 in Claude Code, 117 to 140 in OpenAI Codex). All four probes kept 3 of 3 rules.

**Read version** (`*-read-*`): "Use your file-reading tool, not grep or other shell commands, to
read all of logs/log-N.txt into the conversation. Then tell me the timestamp of the third line
that contains ERROR. Report the timestamp only." Correct answers: 2026-10-11T01:31:09Z, 2026-10-12T00:28:50Z,
2026-10-13T00:53:50Z, 2026-10-14T01:20:14Z, 2026-10-15T00:35:26Z, 2026-10-16T01:33:03Z,
2026-10-17T00:41:36Z.

Each log file is about 43,000 tokens to Claude Code's tokenizer. OpenAI Codex has no file-reading
tool apart from the shell, which the request ruled out. `cx-read-2` read every file through
`node_repl`, a Node.js REPL MCP server installed on the author's machine (not part of Codex),
in 240-line chunks, and a whole file added about 32,000 tokens. `cx-read-1` tried a different
local MCP server, then said it had no tool it could use. With a stock Codex install, expect
`cx-read-1`'s result. A REPL server with file system access also widens what the agent can
reach, so weigh it against the limits from Chapter 2 before you install one. Tool results longer than 2,000 characters are truncated in
the published read-version files (the full logs are regenerated by `make-logs.py`), and one
command output in `cx-read-1` that listed local harness configuration is redacted.

**What OpenAI Codex's automatic compaction kept** (`cx-read-2`, from the session log, which isn't
published because it includes local configuration). The log's `compacted` event replaced the
history with 13 items: the rules message and the first six read requests, word for word, as
`user` messages; Codex's own `developer` instructions and environment context; the seventh read
request; and one `compaction` item whose content is encrypted. No file contents or model replies
remained in readable form.

**The `recordLogin` probe** (`cc-read-*/probe3.jsonl`). After the first probe, which was never
run without rules and so doesn't test whether they survived, both Claude Code read sessions were resumed and given the `recordLogin`
probe from `../../task-ladder.md`, which sessions without rules fail (see
`../2026-10-22-compaction/`). Both kept all three rules (`probe3 aas=3/3` in `scores.txt`) at peak
payloads of 348,009 and 345,914 tokens, adding an update method to `UserRepository` instead of
importing from `db.js`.

**File names.** Each run's `logN.jsonl` is the output of the Nth read request, which the chapter's
procedure saves as `read-N.jsonl`; `probe.jsonl` is the `order-service.js` probe and
`probe3.jsonl` the `recordLogin` probe.
